Contentful's image API errors when the requested `w=` param exceeds the source image's
actual stored width (reporter gives working w=3998 vs failing w=4001 for the same
image). @wynnmade's comment: Contentful "explodes if the request is larger than the
image stored in the backend" - so the fix is clamping requested width to the source
image's natural width (or a safe max) before building the Contentful image URL. Likely
lives in src/lib/images.ts - check how image URLs/srcsets are built there for the
existing width logic before adding a clamp.
